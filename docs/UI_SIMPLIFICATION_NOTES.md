# 插件在线更新：UI 简化意见记录

记录日期：2026-11-24（Asia/Shanghai）

状态：本文档最初只记录设计意见；**其中「0.5.5 实际试用补记」与冗余区块方向已在 v0.5.7 实施**，实施范围与未验收项见文末「0.5.7 实施记录」。实施不代表浏览器视觉验收已完成。

## 背景与用户目标

当前界面展示了较多开发验证、运行状态和安全说明，使用体验更接近开发者诊断台，而不是普通用户的插件更新页。用户认为这些信息不应成为使用插件所需的知识负担。

普通用户的主流程应围绕三个问题组织：

1. 哪些插件有新版，哪些可以更新？
2. 如何选择并确认更新，需要自己做什么？
3. 更新是否成功；失败或无法确认时，下一步怎么办？

核心方向：后台检查可以严格、复杂，前台操作不应跟着复杂。技术证据应退出常规主界面，而不只是给每个证据区块增加折叠框。

## 用户明确指出的冗余区块

| 当前区块 | 反馈与记录方向 |
|---|---|
| 本页面插件同步 | 正常状态不需要一个固定区块，也不必反复显示“未报告同步错误”。真正影响使用的同步异常，才需要简短、可行动的提示。 |
| 更新器自身升级证据 | 原始交接、包核验、Host 行数、门禁及跨实例结果证据由开发人员排障时查看，不作为普通用户的固定阅读内容。用户只需当前版本和本次更新的明确结果。 |
| 最近更新证据 | 不应把内部操作事件或阶段记录逐条堆在主界面。如保留用户历史，候选方向是一个操作对应一条简短结果，而不是同时陈列阶段性“未知”和后续“已应用”。是否保留独立历史入口，待后续决定。 |
| 检查限制与安全边界 | 不应占据常规页面。与当前操作无关的完整限制放文档；需要用户作决定的具体影响，在对应操作前说明。 |

用户提供的截图还显示：旧的 `0.5.0 → 0.5.3` 自身更新记录，与当前显示的 `0.5.4` 及“未知”核验标签并列，容易让用户误以为当前安装失败。此处记录的是界面信息组织问题，不依据截图重新判定安装结果。

## 讨论中提出的保留原则

以下用于后续设计取舍，不代表本次已经实施：

- 保留插件名称、当前版本、可更新版本、选择与更新入口，以及必要的进度和最终结果。
- 更新失败、结果无法确认或需要重启，属于用户下一步操作所需的信息，不能因隐藏证据而被隐藏或改写为成功。
- 停止当前任务、改变安装来源等确需用户决定的事项，仍在操作前保留明确确认；说明聚焦实际影响和选择，避免展开全部内部机制。
- 不要求用户理解归档摘要、Host 条目、代际身份、来源计划、交接回执等技术术语才能完成更新。
- 原始诊断数据保留在插件自有日志或诊断记录中，排障时再读取；如提供日志导出，需要脱敏，不自动上传。
- 隐藏技术证据不等于降低来源校验、兼容性检查、状态复验或未知结果保护，也不等于自动重试未知操作。

## 0.5.5 实际试用补记：简化更新确认弹窗

用户完成 Better Sidebar `0.32.1 → 0.33.0` 更新后指出：确认弹窗放了多段镜像、备用源及宿主说明，还要求勾选多个确认项，真正需要选择的只有「更新前任务处理」。

- **普通更新的确认弹窗**：简短列明所选插件及版本，只保留「更新前任务处理」这一组选择和底部「取消／确认更新」按钮。默认等待当前任务自然结束。不另设「我已核对版本」等通用勾选，不把常规公共镜像说明做成额外的必读、必勾区块。
- 若选择停止当前任务，在该选项旁说明影响，并让确认按钮明确写出「停止当前任务并更新」。默认等待和通用更新确认都不表示同意停止任务。
- 原包比对、镜像下载、备用源及安装校验继续在后台处理，技术信息放诊断详情。只有本次确有需要用户决定的特殊影响（例如安装来源会改变），才用一条针对当前操作的说明和明确确认；不能把显示简化当作放宽后台准入。若现有协议要求独立同意，实施时需验证简洁的新交互仍能表达并绑定该同意，不能默认代勾。

列表也应避免用同一个「条件不满足」笼统概括不同状态：查询源没发现新版、本地安装不支持面板自更新、发现新版但当前不支持在线替换，应分别用简短文案说明，详情可展开。这是针对试用中的困惑补充的设计建议，不改变实际准入。

## 本次范围与后续待定项

本次只维护设计记录，不修改客户端、更新流程、用户配置、历史日志、插件版本或安装状态。

后续实施前还需确定：主页面最小信息布局、简短结果和状态文案、是否保留可选更新历史，以及开发排障入口的位置。实现和浏览器验收应另行进行，不能把本次记录称为界面改造已完成。


## 0.5.7 实施记录

已按本文档实施，范围如下：

- 主流程只保留：勾选与版本、进度、每项结果、诊断入口。
- 「本页面插件同步」「更新器自身升级证据」「最近更新证据」「检查限制与安全边界」合并为一个默认折叠的「诊断与历史记录」区块。页面同步确实失败、自身升级进行中时才回到主流程。
- 列表每行先给一句短状态（可更新／已是最新／需重启 DSH 后更新／本地安装／无兼容正式版／暂不支持在线更新），原包、来源、宿主条目等证据收进该行「详情」。
- 确认弹窗只保留所选插件与版本、「更新前任务处理」、取消／确认；删除通用「我已核对版本」勾选。改变安装来源、公共镜像、派生代际三类特殊影响各自保留独立确认；停止任务仍单独确认，按钮写明停止语义。
- 后台校验未放宽：原包比对、依赖闭包、宿主声明与运行命名空间核验保持原样，只是不再要求用户阅读。

结构断言见 `tests/ui-simplification.test.mjs`。浏览器视觉、窄屏与键盘操作仍未做页面验收。

## 0.6.0 实施记录

- 删除行内「声明差异／未审查表达式」提示与「新版声明待审查」短状态：声明审查本身已从默认路径移除，保留旧文案只会让用户误以为还有一步人工操作。
- 短状态集合收敛为：可更新／已是最新／需重启／本地安装／无兼容正式版／暂不支持在线更新／可恢复旧版。
- 为兼容历史记录，旧原因码的中英文案仍保留在本地化表里，但新的判定不再产生这些码。
- 详情里的依赖与宿主核验证据仍是折叠内容，不回到主流程。


## 0.6.5 实施记录（确认弹窗与检查进度）

- 确认弹窗里的两个来源勾选框（公共镜像/备用源、完整依赖代际）连同勾选文案一起删除；来源迁移的说明改为纯提示。用户明确表示「内容和勾选都不需要，只需要选择那里的替换然后确认或取消」。
- 现在弹窗只保留：插件与版本、影响说明、任务处理（等待/停止）、取消/确认。
- 服务端显式确认没有放宽；面板在对应计划上自动附带 `confirmPublicMirror`/`confirmUnionGeneration`/`confirmMigration`，风险说明仍展示。
- 「检查全部更新」新增真实进度条：查询版本 → 逐包核对 → 完成，显示当前插件、完成数/总数与百分比；来源是 Host 的 `scan-progress`，不是假动画。
