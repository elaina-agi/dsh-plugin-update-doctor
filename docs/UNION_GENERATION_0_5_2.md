# Union 完整依赖代际更新（自v0.5.2起）

## 结论与范围

本页保留0.5.2阶段的Union设计和验证范围，该限定路线由后续版本继承。**自0.5.6起，准入不再写死 `0.10.24 → 0.10.25`：同结构版本按已安装依赖与公开原包证据准入，宿主声明或依赖声明变化仍拒绝。** 详见[依赖隔离说明](<ISOLATED_DEPENDENCIES_0_5_6.md>)。WSL由用户实际更新到0.29.0另见[验证记录](<VERIFICATION.md>)，不能据此声称用户实际执行了Union升级。

本路线只属于独立更新器插件，不修改DSH／Node／Electron或Union原始JavaScript。安装包和运行结果分别核验；安装更新器不会自动更新Union，旧0.5.1包不含此路线。

旧0.5.1的**风险拦截不算修复**；原版管理器的常规npm/HMR更新与自动恢复失败事实仍然成立。本轮新增不同的**完整依赖本地代际归档路径**，不是修好宿主热加载器。

## 新增能力

- 0.5.2 阶段限定已审查公开Union Search `0.10.24 → 0.10.25`；0.5.6 起改由结构化证据准入，不再保存版本对。
- 新版原始插件代码和完整HTML纯JS依赖分别放入全新generation路径；保留旧root资源与前代路径。Host Schemastery/DSH框架保持共享，不复制宿主实例。
- 插件原始JS与依赖文件逐byte核对公开同版本归档，绑定source SHA512／固定SHA256、依赖声明／范围／真实解析关系、布局和完整库存。
- 通过原版公开管理器remove/install，DSH进程保持打开；Union插件会短暂卸载。默认等待Agent自然结束，停止任务需额外同意。
- 更新前生成不同fresh token的目标与恢复归档，恢复包保留目标资源；故意目标失败与原版本功能恢复分开记录。unknown不重发、不自动删除外部目标。
- 确认框额外披露并要求接受来源变化：**npm安装 → 更新器管理的本地完整依赖代际归档**。不是静默迁移，不伪造npm身份，不保留宿主内置Versions资格；后续由更新器根据可信归档身份独立查询公共版本。
- 新身份写schema3，旧schema1/2可读；旧更新器不应被用于继续管理schema3代际记录。
- 已启用条目需实际Host活动及Loader namespace与精确fresh generation一致；已停用目标报告disabled/未执行，不冒称新代码已经运行。
- 手动恢复限已知失败、当前已装完整代际可核验、身份匹配，重新生成fresh oldgeneration。缺包／未知／外部改变不提供可用恢复资格。
- 保留旧代达到上限提前拒绝新操作，不静默删除可能仍被引用的旧路径。

## 已验证与未验证

1. 完整归档原型在未修改Desktop DSH0.2.2-rc.5／Electron44.7.0／Node24.21.0中通过：公开旧24首次到25、故意坏新目标后恢复原24功能、连续五代切换；复制26依赖／2249文件均与公开精确原包核对。
2. 生产DoctorService／UnionGenerationStager／HTTP确认＋默认TaskGate路径在原版自有Host中：正常升级、明确无包命令目标拒绝后的恢复、缺来源同意拒绝均通过；实际advance_fetch字段提取／Markdown、真实本地身份、源/文件/Host/运行代际和持久lineage分别核验。
3. 生产拒绝组是明确fixture拒绝，不能当作实际新版激活故障；原型坏包组是故意module throw，不作为公共包准入。二者不是同一证据。
4. 生产模块以冻结副本运行，前后摘要一致；早期并行编辑造成摘要不符的一轮不计最终通过。
5. 最终归档资源／完整回归／隔离Host安装与本机更新器安装结果，以另行交付的验收记录为准，不把早期冻结结果冒充最终包结果。仍未全面覆盖生产集成的真实激活失败／重复路径，0.5.2浏览器新确认框／主题／键盘／窄屏交互尚未验收。该阶段没有更新或降级用户Union或WSL，也没有停止用户任务。

本路线不保证所有插件、全部依赖、原生依赖、已有Worker/会话无缝连续或恢复永远成功。DSH底层修补研究不属于本版交付。
