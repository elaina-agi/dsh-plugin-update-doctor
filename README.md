# DSH 插件在线更新

**v0.5.3 本地修复版（尚未发布到公共 npm） · 独立第三方插件 · Windows x64**。本机已通过官方管理器安装0.5.3，用户在真实面板确认的WSL `0.26.2 → 0.29.0` 更新已由操作日志、资源核验及16/16活跃Host条目确认成功。公共 npm 已发布版本仍为 **v0.5.0**；下面的npm安装示例对应公共版本，不会获取未发布的0.5.3。本地修复包须经官方管理器另行安装。当前完整隔离验证使用原版DeepSeek Harness Desktop **0.2.2-rc.5**，不修改DSH／Node／Electron；早期普通更新／WSL实验使用rc.3。兼容声明不等于全部宿主版本或另一台设备均经过实测。

主流程：**检查全部更新 → 勾选兼容正式版 → 一键更新所选 → 确认当前任务的处理方式（默认等待结束） → 查看逐项结果**。诊断是失败详情和辅助证据，不是主要操作入口。

> **不是所有插件都支持无重启更新。** 常规Union Search npm/HMR路径仍存在新版及旧版恢复加载失败。旧0.5.1的风险拦截不算修复。自0.5.2起，本插件新增已审查 `0.10.24 → 0.10.25` 的**完整依赖本地代际归档**，在原版DSH保持打开时更新；不修补DSH，不修改第三方JS，不自动重启。
>
> 新路线会明确改变为更新器管理的本地归档，宿主内置Versions资格不保留，需要额外确认。原型／生产限定隔离路径已通过；最终归档和本机安装结果以另行交付的验收记录为准，真实浏览器新确认框、主题、键盘和窄屏交互尚未验收。见[Union代际说明](<docs/UNION_GENERATION_0_5_2.md>)。

这里的支持是限定路径与实际测试范围，不代表所有插件／所有未来声明变化都能更新。WSL 检查通过是准备确认的资格，不等于真实用户安装已成功。

## 安装

v0.5.0 已发布到[公共 npm](<https://www.npmjs.com/package/dsh-plugin-update-doctor/v/0.5.0>)，同时保留 GitHub／本地源码安装方式。2026-11-21 已核验公开版本为 `0.5.0`、`latest` 指向 `0.5.0`，安装包可下载且摘要与已审查归档一致。发布记录见[发布与隐私说明](<docs/PUBLICATION.md>)。

### 推荐：npm 安装

在 DSH 的「插件 → 添加插件」中输入以下包名，由官方插件管理器安装并启用；不要在 DSH 用户 profile 目录手工运行 `npm install`：

```text
dsh-plugin-update-doctor
```

**不必写版本号。** 不带版本号时，安装按 npm 的 `latest` 标签解析目标（本次核验为 `0.5.0`），仍受宿主兼容性与包管理器策略约束。若想明确指定本次已核验版本，也可输入：

```text
dsh-plugin-update-doctor@0.5.0
```

指定版本只决定这次安装目标，**不会阻止以后检查并确认升级**；不指定版本也不意味着自动更新。安装后需要在本插件面板点击检查、勾选并确认，才会安装通过预检的较新兼容正式版。

### 可选：GitHub 完整提交安装

使用 GitHub 来源并希望保留可核验的原来源及自身升级资格时，应固定完整提交，而不是只跟随会移动的分支。v0.5.0 的来源为：

```text
github:elaina-agi/dsh-plugin-update-doctor#7eb59f934ae80ee5636bddfbc79afa67bbc2970e
```

`#` 后面是 **Git 提交号，不是 npm 版本号**。只输入 `github:elaina-agi/dsh-plugin-update-doctor` 可以请求安装仓库默认分支当时的代码，但不能据此认为已保存固定来源；本插件和官方管理器的 Git 更新资格都要求保存的安装来源含完整 40 位提交。固定旧提交不会阻止以后升级：点击检查时，本插件独立发现 `main HEAD` 上更高的正式包版本，经预检和确认后交接到新的完整提交；它不提供同版本不同提交替换，也不是自动更新或 GitHub Release 渠道。

### 可选：本地源码安装

下载仓库 ZIP、完整解压到长期保留的目录，再在「添加插件」中输入该目录的**绝对路径**。本地目录安装可能直接链接源码，安装后不要移动或删除目录；本地／链接安装不支持自身升级。

**已有 GitHub v0.5.0 安装无需重复安装。** npm 发布不会改变现有安装来源；GitHub 安装不自动迁移成 npm。只有固定完整提交且通过预检的此仓库安装，才能使用 GitHub 自更新路径。旧 v0.4.1 尚无该路径，需要先通过官方管理器升级一次。

npm 安装可用不等于 npm 自更新无条件可用：开发版新增固定公共镜像路径，镜像包与官方归档及运行声明一致时需额外确认并绑定公开宿主计划；原官方路径仍保留无 fallback条件。私有／未知来源、固定依赖／助手不符仍拒绝，不擅自改宿主配置。GitHub 路径沿用现有宿主依赖源，详见[自更新保障与限制](<docs/SELF_UPDATE.md>)。

如遇网络或安装错误，请保留官方管理器的具体诊断；不要批准不明脚本或版本豁免。首次安装后的标题、图标和真实面板交互仍需在你的 DSH 页面查看。

## 使用

1. 在左侧打开 **插件在线更新**，点击 **检查全部更新**。初次打开不自动查版本或勾选。
2. 勾选目标（每批最多 20 项），点击 **一键更新所选**。
3. 确认框让你选择**更新前怎么处理当前运行的 AI 任务**（界面称“任务政策”）：
   - **等待当前任务自然结束**（默认，推荐）：不取消任务，等任务空闲后再更新；没有运行中的任务时无需等待它们。
   - **停止当前智能体任务后更新**：必须另行确认。只针对点击确认时运行的活动；之后新启动的任务只等待。停止会清除该活动的排队输入，已完成的工具副作用不能撤销。
4. 包预检查完成后才执行任务政策。随后逐项更新，失败停止后续项并显示真实恢复结果。外部终端、独立 Worker 不会被杀掉。
5. 若自动恢复失败，只有**结果已知、当前安装身份与记录匹配、原包可核验且恢复路径获准**的目标，才可使用 **恢复记录旧版** 并独立确认。未知结果和未获准路径的Union Search不因此获得恢复资格；完整依赖代际恢复另需当前已装原包可核验、重新生成fresh路径，不恢复npm身份。不能输入任意旧版本或路径。

DSH 不自动退出或重启，**普通批次**更新期间暂缓新步骤；自身升级的旧门禁在卸载时释放。离开页面不取消已确认的宿主管理操作；开始替换前可以取消等待。

## v0.5.1 历史开发修复（未发布公共npm）

- 修复 WSL 已校验归档来源使用 npm 精简元数据导致新版被漏掉；新版保持可见，但只有已验证的精确版本／归档才允许走 WSL 代际更新路径。
- 面板把**版本检查**与**在线更新条件**分开：当前查询源没有较新的正式版本，不等于来源／依赖条件已满足；发现新版，也不等于能勾选更新。没有兼容候选、缺失元数据、查询窗口遗漏和网络失败均有不同状态。
- 正确解释 Host `registry: null` 为有效 pnpm 查询源，通过公开 API 前后核验；镜像来源如实显示，不再仅提示“来源未确认”。未知或检查期间变化的来源仍拒绝，不偷偷换源、不修改宿主配置。
- 新增固定公共镜像自身升级，镜像元数据／归档与官方版本独立比对并要求额外确认；不修改安装源配置。普通JS依赖不再仅因dependencies字段被拒，限定不变解析图／字节、无原生或安装脚本的已审查路径。停止任务前及自身交接前加强来源重验。
- 已实际验证 WSL **0.26.2 → 0.28.0**，保留历史0.24根资源及三代归档；新增官方插件详情的独立版本检查入口和打开更新面板。它不伪造官方registry身份。
- 新增已识别旧普通归档的独立同版本来源迁移，用户确认后恢复npm来源，失败保留独立恢复结果；不是自动或任意本地来源迁移。
- **旧0.5.1 Union Search 当前不支持安全无重启更新**：原版DSH rc.5常规npm/HMR目标与恢复实测失败，该版仅拦截风险。本版0.5.2新增的完整依赖本地代际新路线另见上方；它不是修复宿主常规npm热加载，也不让未审查版本自动放行。
- 普通 npm 批量更新改为公开 `pluginManager.updateBundle` 按精确版本交接，保留 `包名@版本` 来源和官方后续版本检查资格；不再把新普通 npm 安装转成本地归档。预下载是核验证据，宿主会按现有安装源／fallback重新下载，不能宣称原子或精确归档替换。
- 更新和宿主自动恢复分别核验真实来源、包字节和预期Host条目；失败不被恢复成功覆盖。只有已知失败、仍匹配记录身份的普通 npm目标才能单独确认按旧版本规格恢复；未知结果不得自动重发、再次更新或恢复同包。
- 旧版已变为本地归档的普通插件不静默迁移；WSL继续现有已验证代际归档路径，因此其官方Versions入口仍受来源限制。失败身份记录升级schema2，新代码读取旧schema1；旧代码不会把新记录误读为归档恢复，但不支持降级旧更新器继续管理新记录。新代码在记录不可核验时停止管理操作。
- 本轮仅更新开发源码和自有隔离测试，未覆盖已发布 `0.5.0`、未安装到用户环境；**不扩展 Mac**，也不宣称全部Windows插件都能无重启更新。见[验证记录](<docs/VERIFICATION.md>)和[Windows支持与边界](<docs/WINDOWS_SUPPORT.md>)。

## v0.5.0 GitHub 自身升级

- 固定公开仓库 `elaina-agi/dsh-plugin-update-doctor`，不接受任意 URL、fork、私有仓库、子目录或分支安装迁移。
- 点击检查后查询 **main HEAD 上更高的正式包版本**，不是 GitHub Release、签名发布或自动轮询；不提供同版本提交替换、降级或 prerelease。
- 扫描、确认及等待后的交接重新核验版本与完整提交；确认框显示新旧提交。Git tree／blob SHA1和运行资源 SHA256分开核验，不执行下载代码或包脚本。
- 只准固定 YAML／助手和不变宿主运行图；Git 打包清单、锁文件、属性控制变化需另行审查。已安装源码必须匹配原固定提交。
- 一次公开 `pluginManager.updateBundle` Git交接；官方管理器安装目标，失败后尝试恢复原固定来源。实际文件、来源提交、Host加载和恢复结果分别核验；恢复不代表升级成功。
- Git路径沿用**现有宿主依赖源配置**，不擅自改 registry／fallback，不批准构建脚本。它不继承 npm路径的 public-only来源保证；网络、依赖源和旧提交消失仍可能使安装／恢复失败。
- 初次升级到本功能需用官方管理器安装固定提交；之后才能在本面板单独勾选更新器。见[自更新保障与限制](<docs/SELF_UPDATE.md>)。

## v0.4.0 自身升级

- 更新器可从本面板发起**独立的宿主自更新交接**：检查后单独勾选，不与普通批次混合。
- 仍默认等待任务，额外停止任务需单独同意。旧更新器卸载时释放门禁，**不承诺宿主替换全程冻结新任务**。
- 后续安装及自动恢复由官方 `pluginManager.updateBundle` 执行；旧更新器不在 disposer 中等待自己的安装。
- 新面板读取单独有界结果记录，并重新核验实际包字节、Host 行和恢复结果。缺失结果保持未知，不自动重发。
- v0.4.0 原有 npm路径仍只准公共 registry、Host 无 fallback 的来源计划、固定 YAML 2.9.1、固定助手和不变运行图；v0.5.0 另加固定仓库 Git路径。本地链接、撤回旧版及其它依赖变更仍需独立处理；不改用户宿主配置。见[自更新保障与限制](<docs/SELF_UPDATE.md>)。

## v0.3.0 设计改进

- 修复目标插件拥有Agent时，维护占位不响应销毁取消造成的等待环；只释放该Agent占位，其他Agent／新正式步骤仍等待。
- 确认前绑定公共npm来源、精确新旧归档及摘要；运行前重新解析实际归档和状态。私有／镜像来源不静默换源。
- 批量失败可按插件查询；精确失败恢复有独立身份记录与额外用户确认，面板只接受记录中的旧版本，诊断工具不执行。
- 安装身份和恢复记录不依赖会轮转的日志；历史内存／磁盘按80条和2MB完整UTF-8预算裁剪并标明截断，I/O失败单独显示。
- 包安装／Host激活／当前页面同步分层显示；页面同步可独立重试，安装进度沿用官方事件。
- 不称原子替换或全执行冻结；外部管理／CLI可介入，归档缓存不能直接删除。详见[设计与验证](<docs/V0_3_DESIGN.md>)。

## WSL 代际语义与边界

新 Host 条目和新会话使用新代际；已绑定旧预设的会话可能继续保留旧实现。更新包同时保留旧根路径运行资源，防止旧代码使用的脚本被替换后摘要不一致。不调用仅适用于空白会话的预设重绑 API 来绕过已有会话锁。

**Host 条目更新成功不等于所有已有 WSL 会话强制换代。** 本轮没有运行真实 WSL 模型任务或验证发行版命令连续性；如需要已有会话立即使用新预设，使用新的会话。会话历史不被删除。用户已提供0.5.3中文深色面板截图，确认候选可选与版本显示；未用模拟页面冒充验收，仍未覆盖所有主题、英文、键盘和窄屏交互。

目前的WSL新候选按公开原包、现代声明契约、宿主兼容性及实际安装身份预检，不再仅限固定版本名单。声明契约保持不变并通过完整预检的未来正式版可进入同一路线；执行代码变化仍可能失败，不能把准入当作未来版本已实测。运行中的更新器自身使用单独的宿主交接路径，并非普通批次；宿主管理核心、未获准依赖图和不支持来源仍需独立更新路径，不能承诺任意插件都能无重启热替换。

## 安全与隐私

- 官方 `pluginManager` 管理配置和安装，不手工改 profile、不改宿主内核，不授权脚本/版本豁免、不提权。
- 普通 registry 插件先准备并校验新旧包再替换。WSL 使用已验证代际包装，保持基础服务抑制配置不变。
- 支持的公共镜像操作额外确认；版本查询源和安装源计划分别核验。镜像可能延迟，私有／未知来源不静默迁移。
- 首轮版本查询复用 DSH 查询源；预下载限定公共 npm 官方源。普通 npm更新使用官方按版本路径并保留来源，宿主重新下载及fallback不是预检归档替换；WSL和旧归档恢复仍使用校验的本地包。私有/Git/开发链接不自动迁移。
- 更新、恢复、停止活动的结果分别记录；权限问题不直接当作占用，文件使用进程不直接当作锁故障原因。
- 原生助手只检测，不关用户进程或强解锁。日志位于 DSH home 的 `cache/dsh-plugin-update-doctor/<profile>`，路径和常见凭据保守脱敏，不上传；分享前仍须检查。
- 需重启、加载失败或未知结果不标为成功。外部同时卸载更新器/修改共享服务存在宿主并发限制，不建议操作。
