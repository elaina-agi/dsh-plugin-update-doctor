# v0.5.6：依赖隔离更新改为结构化准入

- **不再按版本号逐对放行。** Union Search 一类插件的隔离更新现在依据已安装包的真实结构与原包证据准入；同一结构下的后续正式版沿用同一路线，不需要再次修改更新器。
- **宿主声明必须一致。** 行、导出、`main`、`dsh` 声明、peer、平台和固定插件行按原包比对；依赖声明按范围比对。动态声明、include 和覆盖已有行仍拒绝，并给出具体原因。
- **完成条件是实际运行。** 只有官方管理器 applied、安装字节一致、Host 行激活且 Loader 运行的确是新路径模块，才算更新成功；包命令退出 0 不算。
- **恢复是独立结果。** 目标失败后用不同 token 的旧版代际归档恢复，并分别核验字节与实际运行状态；未知结果不重发。
- **来源变化如实告知。** 安装来源变为更新器管理的本地归档，不伪装成 npm 安装，也不保留内置 Versions 资格，需要单独确认。

原版 DSH 0.2.2-rc.5 的隔离验证中，`0.10.25 → 0.11.0` 结构化更新成功并在实际运行代际上通过功能检查；注入一次目标安装拒绝后，旧版也恢复为可实际运行的代际。该实验使用的是公开 npm 原包与真实包命令，但传输与依赖证据由自有隔离配置提供，不是用户实际安装、浏览器交互或第二台设备验收。
