# 更新准入审查：还剩哪些“太严”的校验（0.5.10 现状）

日期：2026-11-25（Asia/Shanghai）
范围：`lib/` 内 195 个错误码，以及扫描/准备阶段真正决定“能不能勾选”的判定。

## 先更正上一轮审查里的两条错误

1. **“普通插件声明逐字节不变”并不存在。** 普通路线只比对 **peer 图**与**运行时依赖声明**，并不钉 patch 文本；`declaration-changed` 不是普通路线的判定。WSL 才有声明契约。
2. **“本地来源按字节证明后允许更新”对你没有实际帮助。** 该方案要求本地归档字节等于 npm 上同一版本的归档；你本机安装的是每次现打的发布归档（0.5.8/0.5.9/0.5.10），npm 上并不存在这些版本，所以判定必然失败。本机 doctor 真正的“更新”只能是换一个新的本地 tgz，或者发布到 npm。

## 真正仍然过严的一条

**依赖声明变化一律拒绝**（`dependency-graph-changed`；隔离路线不可用时还会出现 `dependency-runtime-reload-unverified`）。

- 现状：普通路线要求新旧版本 `dependencies` / `optionalDependencies` / `peerDependencies`（peer 另判）完全一致；只有命中写死的隔离条件——包本身是 `dsh-union-search`，或依赖里正好有 `cheerio`+`turndown`+`@joplin/turndown-plugin-gfm`——才走隔离代际。
- 影响：任何其他纯 JS 插件，只要某个次版本加/删/换依赖，就永远无法通过面板更新。这正是你反对的“按包写死”。
- 为什么没在本轮顺手改：隔离代际现在是从**已安装的依赖树**复制出 `g/<hex>` 闭包。依赖发生变化时，新依赖尚未安装，必须从公开 npm 下载并按 SRI 校验后解包进代际，再重新绑定宿主声明、做一次全新 Host 证明。这是个独立工作项（预计 150 行生成器 + 一套 Host 证明），不能在现有代码上只改一行判定。

## 两条“麻烦但有理由”的

| 校验 | 现状 | 可选放宽 |
|---|---|---|
| `no-compatible-stable-version` / `staged-version-incompatible` | 引擎声明与运行中的 DSH 不匹配即拒绝 | 加“明确同意后仍更新”，默认仍拒绝（官方管理器有同类 exemption） |
| 隔离路线只接受稳定版（`canInspectIsolatedPair`） | 预发布目标一律不可选 | 预发布单独确认 |

## 该继续拦的（复核后确认必要）

安装脚本、原生依赖、vendored 二进制；核心服务覆盖；归档完整性/tar 路径/SRI/manifest 身份；Host peer 图变化；row-id 冲突；未知结果不重发；保留上限；镜像与来源白名单；文件占用预检（只是提示）。

## 本轮附带确认

新增回归：**目标版本新增核心行覆盖会被拒绝**（`existing-row-override-unsupported` / `core-service-takeover`），说明“新版本偷偷接管核心服务”这个口子是堵住的，不需要新代码。

> 2026-11-26（0.6.6）修正：这里的判据从「只要目标带核心行覆盖就拒绝」改成「**相对已安装版本新增或改动**核心行接线才拒绝」。同时标准通道不再因 patch 含 override 条目整包拒绝——否则像 `dsh-unlag` 这类改写 `hmr` 配置的正常插件会永远无法在线更新。目标仍然不能在更新中偷偷获得新的核心服务控制权。

## 结论

- 结构性问题只剩“依赖声明变化”一条，修它需要新的闭包生成器。
- 想让更新器自己能持续升级，最省事的路径是**发布到 npm**（发布后它就是注册表来源，可正常自更新）；否则每次都要手动换本地 tgz。

## 0.6.0 处理结果（2026-11-25）

- **依赖声明变化**：普通通道不再拒绝。理由：普通包本来由官方 npm 更新负责解析依赖，预下载闭包不是必要条件；改为装后按新清单核验实际解析树（容错记录未安装的可选依赖），拒绝原生字节与非法来源，不通过自动回滚。原计划“150 行闭包生成器”只在隔离代际路线仍然需要。
- **peer 图变化**：复核后也删掉了预拒绝。peer 值本来由 Host 的 registry stager 校验，插件装不上会体现为激活失败；保留的是 peer 键值语法检查和宿主运行时依赖拒绝。
- **`dependency-runtime-reload-unverified`**：只保留给按结构选中的隔离路线（Union/HTML 闭包），不再作为普通插件的兜底。
- **预设/声明审查**：WSL 结构摘要、`!!js` 表达式登记、现代行集合、固定导出键、固定 peer 键集全部删除；核心供应者抑制、受保护行、terminal 覆盖仍保留。
- **保留清单不变**：安装脚本、原生依赖、核心服务接管、row-id 冲突、来源白名单、未知结果不重发、保留上限、文件占用提示。
- **界面**：删除「新版声明待审查」短状态与行内声明差异提示；旧原因码文案保留给历史记录，但不再产生。
- **仍待做**：隔离代际的闭包下载与物化（`dependency-closure-requires-download` 之后的一半），以及真实 npm 依赖变化端到端证明。
