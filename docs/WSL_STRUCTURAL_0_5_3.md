# v0.5.3：WSL 新版准入修复

本版修复更新器把 WSL 新版仅因不在固定版本名单中而提前拒绝的问题。0.5.2 能发现 0.29.0，却以 `wsl-version-not-yet-verified` 禁止勾选；这不是 WSL 安装故障，也不是兼容性测试失败。

## 新的检查方式

- 检查稳定正式版的公开 npm 原包、SHA512、精确包名/版本、宿主兼容性及平台。
- 对新候选核验现代 WSL 的完整声明契约：16 个既有 Host 行、基础服务抑制、预设及配置表达式、11 个既有 peer 名称、客户端注入图、导出资源和安全路径。声明变化会给出具体契约拒绝原因，而不是“没有测试这个版本号”。
- 不引入新运行依赖、不批准安装脚本、不复制或修改宿主；已有 Linux agent 原生资源只在受限原路径内保留。
- “检查全部更新”对候选只读下载/检查，不写 stage、不安装、不停止任务。准备确认时再次下载、绑定候选摘要及实际已装资源，确认后及等待后重验。
- 新的代际身份保存 root 与全部 retained 原包的版本、SHA256/SHA512 和独立原包证明，重新打开时离线重建整个派生归档。旧身份仍可读，新 WSL 结构身份使用 schema4；不能降级旧更新器继续管理 schema4。
- 最多保留 8 个原包并受原来的 2,000 项归档和字节上限限制，超过上限提前拒绝，不静默删除旧代。
- 初次安装、第二次公开 reapply 或恢复回执未知时均不自动恢复或重发。未知恢复身份在准备、已发票据、任务政策前和实际恢复入口拒绝。

旧 0.24.0 / 0.26.2 / 0.28.0 的固定摘要只用于验证既有历史原包和保留根资源，**不再充当新候选版本名单**。

## 本机用户后续升级确认（2026-11-23）

0.5.3完整归档安装完成后，用户在真实面板确认WSL **0.26.2→0.29.0**，日志时间 **22:12:13–22:12:29（Asia/Shanghai）**。操作applied、包命令exit0、generationVerified=true、资源核验通过，当前Host **16/16active**，没有触发旧版恢复。此项是用户真实升级证据，不再仅是隔离实验；不等于发行版任务、全部已有会话或第二台设备已验证。中文深色截图还确认新版本列表和候选可选，完整主题/英文/键盘/窄屏行为仍未覆盖。

## 实际验证与限制

- 公开 WSL 0.29.0 的 Host patch、peers、导出与 0.28.0 不变；主要变化为客户端、状态模块和文档。
- 原版 DSH Desktop 0.2.2-rc.5 隔离 profile 中，保留 0.24 根资源的 0.26.2 基线通过完整生产 HTTP prepare/commit、默认等待、0.29.0 代际更新，Host 15 → 16 active；替换前准备的旧包经公开管理器恢复后 15 active。新旧代和根资源按公开原包逐 byte 核验。
- 结构专项验证不是未来版本实际安装成功承诺。源码结构保持不变的未来正式版可以进入同一检查流程；变更执行代码仍可能发生加载错误，因此保留结果核验和恢复路径。
- 实验使用自有临时 profile、公共原包传输 adapter、panel-shaped 请求，没有运行真实 WSL 发行版、模型任务或浏览器点击。预准备旧包的恢复通过不等于每个实际激活失败恢复都验证。
- 0.5.3打包时回归358项（344通过、14明确跳过、0失败），同一最终归档47文件已核验，冻结生产模块与其摘要一致。后续文档补记不覆盖该归档，不把早期冻结结果冒充最新代码复验。
- Windows x64并非唯一环境条件；Node/Host及.NET Framework4.x辅助要求、另一台设备未验证的边界见[运行要求](<WINDOWS_REQUIREMENTS.md>)。
- 安装更新器本身不会自动更新WSL / Union；本机WSL的后续升级由用户另行确认，WSL 来源仍是本地代际归档，不伪造 npm / 内置 Versions 身份。已有会话可能保留旧预设。
- 本版不扩大 Union 的已审查升级对，不修改 DSH / Node / Electron，不重启或杀进程；仍不代表“任意插件都能更新”。
