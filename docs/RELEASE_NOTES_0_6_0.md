# v0.6.0：标准更新通道

0.5.x 的默认路径把“审查”当成了准入条件：peer 图一致、依赖声明不变、WSL 结构摘要与 `!!js` 表达式逐条登记、Better Sidebar 固定版本对、Union 宿主声明摘要一致……结果是正常的版本更新经常被这些理由挡住，而其中大多数差异并不比插件本身的代码更危险——插件代码本来就在 Host 里运行。

0.6.0 把默认路径改成**标准通道**，只保留四件事：

1. 来源是已批准的公开 npm；
2. 目标归档按 SRI／SHA256 逐字节核验；
3. 旧版本原包已暂存并核验，作为回滚归档；
4. 安装完成后独立核验：官方返回 applied、安装字节与目标一致、Host 行激活、实际依赖树符合新清单。

不满足第 4 条就自动回滚并如实记为失败。

## 删掉的“审查”闸门

| 旧校验 | 0.6.0 |
|---|---|
| `peer-graph-change`（peer 声明逐字节一致） | 不再预拒绝；装后由 Host 行与激活结果核验 |
| `dependency-graph-changed`（依赖声明变化即拒绝） | 普通通道不再按声明预拒绝；装后按新清单核验实际解析树 |
| Better Sidebar 固定 `0.32.1 → 0.33.0` 原包对 | 删除；`!!js` 停用声明作为惰性 YAML 数据解析，不执行 |
| WSL 结构摘要 `e820e82c…`、`!!js` 表达式审查 | 删除；行集合与表达式不再逐版本审查 |
| WSL 现代行集合 `MODERN_ROWS`、固定导出键清单、peer 键集 | 删除；改为形状校验＋装后核验 |
| Union 宿主声明摘要必须一致、`0.10.24 → 0.10.25` 特例 | 删除；代际从新版本自身声明生成，装后核验 |

## 依赖变化怎么处理

- **普通插件**：允许声明与 peer 变化。装后 `inspectDependencyGraph` 按新清单检查已解析树：拒绝原生字节（`.node`/`.dll`/…）、非法路径、解析版本不满足范围；浏览器内置或平台可选依赖解析不到时记为未解析证据，不阻断。
- **隔离代际（Union 等）**：闭包仍必须自包含。依赖范围变化时，已核验闭包满足新范围就复用现有副本；满足不了报 `dependency-closure-requires-download`（下载并物化闭包是 0.6.x 的下一半，尚未接入）。

## 仍然拒绝的东西

核心服务接管（`subprocess`/`fs-sandbox`/`session`…）、安装生命周期脚本、原生或共享运行时依赖、宿主运行时依赖（`@deepseek-ai/dsh-*`、`node-pty` 等）、自更新混批、管理包与只读包、非法 / 私有 / 不可核验来源、`.node` 等原生字节、行 id 冲突。这些不是“审查意见”，而是会在验证前执行或会破坏 Host 回滚能力的事实。

## 界面

- 删除行内「声明差异／未审查表达式」与「新版声明待审查」短状态；它们对应的判定已不存在。

- 真实原包只读复核：Better Sidebar `0.32.1`（`cd0a88c0…`）与 `0.33.0`（`90d003cf…`）都通过**通用** staging 路径，行集合仍为 `better-sidebar`；WSL `0.29.1` 真实原包通过新 `inspectWslCandidate`，结构摘要 `e820e82c…`。
- 本机真实 profile 只读复算：sidebar 0.33.0（2 包 / 252 文件）、doctor 0.5.11（1 / 233）、WSL 0.29.1（0 / 0）、Union 0.11.0（29 / 2289）的容错依赖树核验全部通过，无未解析项。
