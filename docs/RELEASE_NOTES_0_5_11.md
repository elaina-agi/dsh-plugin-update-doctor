# v0.5.11：隔离路线接受“闭包已满足”的依赖范围变化

日期：2026-11-25（Asia/Shanghai）

## 改动

隔离代际路线原来要求新旧版本的依赖声明**完全相等**，否则 `union-declaration-changed`。现在改成核对语义：

- 依赖范围变化时，逐个检查**已核验的已安装副本**版本是否满足新范围（`unionRangeMatches`）。
- 满足 → 继续用现有闭包组装代际（代际里放的本来就是这些已核验副本，语义仍然正确）。
- 不满足，或新版本引入闭包外的新依赖 → `dependency-closure-requires-download`，明确拒绝并说明需要下载路径。

这解除了“依赖范围挪动就永远更新不了”的一类拒绝；真正需要新依赖的版本仍拒绝。

## 验证

- 完整回归：**412 项通过、0 失败、0 跳过**（串行）。
- 新增断言：范围被满足时通过；副本版本不满足时抛 `dependency-closure-requires-download`；无快照时同样拒绝。
- 未做：从 npm 解析并下载新闭包、组装代际的下载器——这是这条路线剩下的一半。
