# v0.6.9：只留「能回滚」的前提，其余不再拦

按你的要求做到极限：面板只在**没有可信回滚**时才拒绝，其余一律放行，装完看事实，坏了回滚。

## 现在还会拒的（就这几条，都不是「形状」判断）

| 前提 | 为什么必须留 |
| --- | --- |
| 公开源 + 精确版本 + 归档字节/SRI | 不知道装的是什么、也没有可信的回滚包 |
| 回滚归档必须可用且核验 | 没有它就没有「失败了回滚」 |
| 自身包走独立流程 | 更新器替换自己会在途中卸载，不是校验问题而是执行路径 |
| 已安装树里**已有被宿主加载的原生二进制**（`native-payload-not-hot-replaceable`） | 实测 `dsh-meme`：更新时 pnpm 无法重命名被锁的 `sharp` 目录（`EPERM`），插件被卸掉后连回滚也写不回——这是「回滚救不回来」本身 |
| 非 profile 管理包（宿主自带 / 只读） | 不是我们的包 |

## 这一版删掉的（原来会拒）

| 原拒绝 | 现在 |
| --- | --- |
| `preinstall/install/postinstall` 安装脚本 | 放行。pnpm 默认就不执行依赖的构建脚本，DSH 管理器读 `pendingBuilds` / `allowBuilds`，要用户显式批准才会跑 |
| 依赖里 `git:` / `http:` 来源 | 放行，交给 pnpm 与回滚 |
| 依赖里出现 `@deepseek-ai/*`、`electron`、`node-pty` 等宿主运行时包 | 放行。官方管理器自己会检查「是否改动了别的直接依赖」并在必要时撤销（`unexpected-package`） |
| 相对已安装版本**新增**核心行接线（`core-service-takeover`） | 放行，只在计划/检查结果里记 `coreWiring: true` 作为证据 |
| 声明里的原生依赖（`sharp` 等） | 放行；只有当**已安装树里真的有原生文件**时才拦（见上表） |

## 代价（唯一一条）

如果某次更新的新 patch 让**宿主启动不起来**，回滚代码没有机会运行——它是宿主里的插件，宿主没起来它也跑不到。此时只能下次启动后用官方管理器手动卸载/回退。这类在 20+ 款实测里一次都没出现，但它确实是「不拦」唯一兜不住的情况。

## 验证

- 回归 **445 项通过**（Node 24 串行）；原先断言「原生依赖 / 核心接线 / 安装脚本被拒」的用例，改成断言「被记录、可继续」，并新增一条「已安装树含原生文件时仍拒」。
- 纸面审计 24 款真实插件：全部通过准入（`git:` 依赖那款也不再拒）。
- 实测：`dsh-meme`（可选 `sharp`）在删掉原生门槛后走完整流程，结果 pnpm 报 `[ERR_PNPM_EPERM]` 重命名 `@img/sharp-win32-x64` 失败，插件被卸载且回滚装不回——因此把这一类恢复为唯一例外。

## 限制

- 「不拦」意味着面板不再替你判断风险；失败靠回滚，宿主级损坏只能手动处理。
- 浏览器渲染/点击未验收；确认票据由测试代签。
