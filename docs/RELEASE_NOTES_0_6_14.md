# v0.6.14：删掉「镜像一致性预比对」

你问「这个有必要吗」——答案是不必要，已经删了。

## 为什么没必要

那一步的意图是：更新前把镜像上同版本的元数据和整包再拉一遍，跟官方 npm 的包比对，证明「镜像给的东西和官方一致」。

但实际上：

1. **我们预检查用的归档本来就取自官方 npm**（`stage()` 固定向 `registry.npmjs.org` 取元数据和 tarball），不是镜像；
2. **镜像的一致性在装后已经被验证**：安装完成后，我们会把 **profile 里实际装上的文件**（来自你的镜像源）与 **暂存的官方归档**逐字节比对——不一致就判失败并回滚。这比更新前再下载一遍更直接，因为它验证的是真正落盘的内容；
3. 那一步的代价是**每个镜像来源的插件多下载一次整包**（9MB 的 `dsh-cost-meter` 就是两次下载），还会因为 `./bin` 这类规范化差异误判（0.6.13 修的就是它）。

## 本版改动

- 删除 `stage()` 里的镜像元数据/整包二次比对（以及随之而来的 `mirror-runtime-metadata-mismatch`、`mirror-archive-mismatch` 一类拒绝）；
- 镜像归档的「一次精确 CDN 跳转」支持保留（`fetchRegistryArchive` 仍只允许那一条规范路径）；
- SRI、归档字节、装后逐字节核验、失败回滚全部不变。

效果：镜像来源的检查少一次整包下载；不会再出现「镜像运行声明与官方原包不一致」这种误判。

## 验证

- 回归 **449 项通过**，其中镜像相关用例已改为断言「预检查只访问官方源、镜像归档只允许一次 CDN 跳转、非规范跳转仍拒绝」。
- 打包与冒烟见 `artifacts/release-0.6.14/`。

## 限制

- 不再声称「更新前已证明镜像与官方一致」；现在的保证是「装后按官方归档逐字节核验，不一致就回滚」。
