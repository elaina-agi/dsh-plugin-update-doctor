# v0.6.8：按「少拦、装完看事实、坏了回滚」砍掉一层静态门槛

这一版是照你定的方向改的：不再为「形状」拒绝，只保留**回滚救不回来**的那几条。装完靠事实判断——版本、字节、Host 行是否 active；不行就回滚。

## 砍掉的门槛（都改成记录或警告）

| 原门槛 | 现在 |
| --- | --- |
| patch 里行名必须属于自己的包（`foreign-or-nested-plugin-row`） | 不再判断，套装子包、外部包名都记录 |
| 行 id 看着像核心服务（`protected-or-duplicate-row`） | 不再按名字前缀拒绝；只在**新增**核心行时按能力差异拦 |
| group 行 / 嵌套子行 | 正常解析并记录（之前直接拒绝） |
| 行名是包内相对模块路径（`./packages/x/lib/index.mjs`） | 正常解析 |
| `bundledDependencies` | 不再预拒（归档字节核验本来就覆盖） |
| 归档里有原生库或 `node_modules`（`native-or-vendored-archive-unsupported`） | 记录，不再拒绝 |
| 依赖树里有 `.node/.dll/.exe`（`native-or-shared-runtime`） | 记录到 `native` 证据，不再让整次更新失败 |
| 装后依赖范围不符（`dependency-version-range-mismatch`） | **警告但继续**（按你的决定） |
| 依赖树检查不出来 | 已经是容忍（记为未知） |

patch 解析器现在只做一件事：把 `insert` / override / group 子行如实读出来，校验 id 唯一、路径安全、YAML 合法、大小与深度有界。**是否允许更新，交给「新旧能力差异 + 装后事实」。**

## 仍然保留的（回滚救不回来的）

| 门槛 | 为什么 |
| --- | --- |
| 公开源 + 精确版本 + 归档字节/SRI | 不知道装的是什么、也没有可信回滚包 |
| 回滚归档必须可用且核验 | 没得回滚 |
| `preinstall` / `install` / `postinstall` | 装的时候就执行了代码，回滚不撤销 |
| 依赖里带 `git:` / `http:` 来源 | 同上（git 依赖会跑 `prepare`） |
| 依赖里出现 `@deepseek-ai/*`、`electron`、`node-pty` 等宿主运行时包 | 换掉宿主内核，插件级回滚救不回来 |
| 相对已安装版本**新增**核心行接线 | 可能把宿主弄到起不来，回滚流程跑不到 |
| 自身 / 宿主管理包 | 不能自己卸自己 |

## 实测

- 纸面审计 24 款真实插件的最新 patch：**23 款解析通过**，仅 `ds-harness-remote` 仍被拒绝——它的依赖里有非注册表来源，属于「安装期执行代码」，保留。
- 之前被挡的三款：
  - `dsh-remote`：之前因归档含 `node_modules`（打包依赖）被拒；改后能通过检查。但实测里它在安装后会被解析到最新 `1.x`（1.4.1 → 1.5.0），检查时面板因此报 `state-changed` / `no-update`，而不是策略拒绝——这是安装源解析行为，不是我们的准入卡口。
  - `dsh-mnemon` 0.5.54 → 0.5.55、`dsh-mobile` 0.8.16 → 0.9.0：**我们这边已放行**，但官方管理器的 `updateBundle` 自己撤销了安装并返回 `unexpected-package`（它会新增/改变另一个直接依赖）。这是宿主侧的保护，不是我们的门槛；面板如实记为失败，旧版本保留。
- 回归 **445 项通过**（Node 24 串行）。

## 限制

- 只砍「形状」类门槛；`git:`/`http:` 依赖与安装脚本仍拒绝，因为它们真的会执行代码。
- 官方管理器自己的撤销（`unexpected-package`）我们无法绕过，只能如实上报。
- 没有浏览器控制，客户端渲染/点击未验收；确认票据由测试代签。
