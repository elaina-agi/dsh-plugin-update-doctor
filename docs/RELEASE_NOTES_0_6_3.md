# v0.6.3：失败详情保留与剪贴板兜底

0.6.2 加了“复制诊断报告”，但还有两个实际缺口：历史被压缩后旧失败可能只剩错误码；剪贴板失败时提示“手动选择可见 JSON”，可报告根本没显示。0.6.3 把这两条补上。

## 失败详情单独保留

新增 `failures.json`（与 `history.json` 同目录），在批次结束时记录终态失败/未知项：

- 最多 10 条、每条诊断 16,000 字、文件 ≤192KB，独立于历史的 80 条 / 2MB 预算；
- 保留错误码、脱敏消息、步骤、恢复结果、装后核验状态和安装模式；
- 重启 DSH 后，历史可能已经裁掉文本，但报告里的 `failures` 仍能说明当时发生了什么；
- 写盘失败只置警告，不会把失败结果改成成功，也不影响更新动作本身。

## 剪贴板失败时直接显示 JSON

复制失败时，报告 JSON 以只读 `<pre>` 展开显示（`data-testid="pud-report-json"`），可以选中、Ctrl+C；提示语同步改成“请选中下面的 JSON 手动复制”。复制成功时也保留一个默认收起的「报告 JSON」入口。

## 面板当前错误也进报告

复制报告时会把当前面板错误（`client.lastError`）并入报告。这样准备阶段被拒（例如 `dependency-closure-integrity`）也有错误码和消息，不必等到批次执行。

## 验证

- 回归 **426 项通过**（0 失败）。
- 失败日志：写入 5 条、上限 3 条时保留最新 3 条；重载后一致；路径与 `password=` 凭据脱敏；文件 ≤192KB；超大诊断带截断标记。
- 报告：`failures` 字段存在且保留错误码、消息、核验状态；`persistence.failureLogWarning` 可诊断写盘失败。
- UI：工具栏、失败行、详情页按钮沿用 0.6.2 的渲染测试；剪贴板兜底是源码级标记，浏览器视觉与真实剪贴板仍未验收。

## 限制

- 失败详情只覆盖面板发起的批次；管理面板之外的官方操作仍只有官方返回的码；
- 不含浏览器控制台或宿主内部完整堆栈；
- 浏览器剪贴板权限、视觉与第二台设备仍未真实验收。

## 安装

在 DSH 面板卸载当前版本后，用「添加插件」选择
`artifacts/release-0.6.3/dsh-plugin-update-doctor-0.6.3.tgz`。
