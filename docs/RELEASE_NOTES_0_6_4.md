# v0.6.4：检查提速与网络失败区分

「检查全部更新」慢，主要有两个原因：每一次检查都会把已安装版本和目标版本两个**完整归档**重新下载、校验一遍；所有候选又是一个接一个串行检查。某次网络抖动还会让整行变成「暂不支持在线更新」，看起来像策略拒绝。

## 做了什么

**复用已验证的只读检查（10 分钟）。** 同一「来源｜插件｜版本」的检查结果在内存里保留 10 分钟，重复点击不再重新下载归档；复用前会核对 npm 元数据的 integrity，发布内容变了立即失效。Union 的公开依赖证明同样在进程内复用，第二次预检查不再重复下载全部依赖包。

**并行检查。** 同一个插件的旧包和新包现在同时检查；扫描列表里最多两个只读预检查并行。

**网络失败不再伪装成「不支持」。** 归档下载失败、连接被重置、超时这类错误，现在在行内显示为「更新前检查失败，可重试」，并说明这是网络问题而不是策略拒绝；下次点「检查全部更新」即会重试。策略拒绝（原生依赖、脚本、核心接管等）的文案不变。

## 实测

- npmmirror 源第二次全量检查：约 50 秒 → 约 13 秒。
- npm 源（真实 Union 依赖闭包）：约 90 秒 → 约 35 秒。
- 回归 430 项通过，0 失败。

## 边界

- 缓存只在更新器进程内，重启 DSH 后第一次检查仍是完整下载；
- 复用条件是「同一来源、同一插件、同一版本且 npm integrity 未变」；任何一项变化都会重新下载并校验；
- 并发上限 2，不会为了提速把依赖检查的严格性放宽。
