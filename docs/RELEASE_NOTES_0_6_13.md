# v0.6.13：修镜像来源的误判（`./bin` 规范化）

你在面板里看到 `dsh-trust-check` 和 `dsh-cost-meter` 显示「镜像运行声明与官方原包不一致，已拒绝更新」，原因不是插件的问题，是我们的比对太字面了。

## 原因

你的 profile 查询源是 `registry.npmmirror.com`。为了确认镜像的元数据与官方包一致，我们比对 `bin`、`main` 等运行字段。实测发现：

- npm 的元数据会把 `"./bin/trust-check.mjs"` 规范化成 `"bin/trust-check.mjs"`；
- 发布出去的 tarball 里的 `package.json` 仍保留 `"./bin/trust-check.mjs"`。

两个字符串不相等，于是被判「不一致」——但它们是同一个路径。这两个插件恰好都有 `bin`，所以只有它们被拦。

## 修复

镜像一致性比对现在会把 `bin` / `main` 的 `./` 前缀规范化后再比较（其余字段、字节、SRI 校验都不变）。我已用真实包验证：

- `dsh-trust-check@0.2.6`（镜像来源）→ 预检查通过；
- `dsh-cost-meter@1.9.94`（镜像来源）→ 预检查通过（第一次下载遇到一次网络中断，重试即通过）。

## 验证

- 回归 **450 项通过**（新增 1 项：镜像元数据 `bin` 无 `./`、tarball 有 `./` 时仍然放行）。
- 打包与冒烟见 `artifacts/release-0.6.13/`。

## 限制

- 只规范化路径前缀，不做其他字段的等价判断；真正的字节与 SRI、归档完整性校验没有放松。
- 镜像下载仍可能遇到网络中断（表现为可重试的失败），不影响判定本身。
