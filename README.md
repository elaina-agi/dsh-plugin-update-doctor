# DSH 插件在线更新

**v0.6.3 · 独立第三方插件 · Windows x64**

在 DeepSeek Harness 保持运行时，检查插件版本、选择符合条件的更新，并通过官方插件管理器完成安装。主流程是：

**检查全部更新 → 勾选兼容正式版 → 一键更新所选 → 确认任务处理方式 → 查看逐项结果**

诊断是失败详情和辅助证据，不是主要操作入口。**不是所有插件都支持无重启更新**；发现新版不等于它可以安全替换。

## 安装

在 DSH 的「插件 → 添加插件」中输入：

```text
dsh-plugin-update-doctor
```

由官方插件管理器解析 npm 的 `latest` 并核对宿主兼容性。可用版本以管理器的实际查询为准，本说明不保存会过时的 npm 标签状态。指定某个已提供的版本只决定本次安装目标，不妨碍后续检查并确认升级。不指定版本也不意味着自动更新。

不要在 DSH 用户 profile 目录手工运行 `npm install`。

### GitHub 与本地安装

- **GitHub**：使用仓库 `elaina-agi/dsh-plugin-update-doctor` 的完整40位提交号固定来源。提交号不是 npm 版本号；从仓库选择与目标版本对应的提交，不使用分支或短提交号代替。固定来源安装可按下述规则自身升级。
- **本地包或源码目录**：通过官方管理器添加当地可读的归档或绝对目录。源码目录可能被链接，安装后不要移动或删除。本地文件和链接来源不支持面板自身升级。
- npm 发布不会把现有 GitHub／本地安装自动迁移成 npm。

### 已被旧版来源检查阻止的用户

0.5.4修复了官方 npm 首选加固定公共备用源被拒，以及 npmmirror 正常 CDN 下载跳转被误拦的问题。修复要由实际运行的更新器代码执行：旧版如果已经不能进入自身更新，需在官方插件管理器中安装包含修复的版本，完成一次引导升级。**无需为此修改全局源或安装配置助手**。不能将这次引导安装称为旧版在原配置下成功自更新。

## 使用

1. 从左侧打开 **插件在线更新**，点击 **检查全部更新**。初次打开不自动查版本或勾选。
2. 查看每项的**版本检查**与**在线更新条件**。普通 npm 候选在只读的新、旧公开原包（含 SRI 与字节摘要）核验通过后才可勾选；当前依赖树只作证据，不再据此预拒绝。下载或校验失败保留“发现新版”，并说明具体原因。扫描不生成 stage 或确认票据；准备和执行前仍重验。镜像未发现新版只代表该源的结果；查询失败、元数据不完整或候选窗口有遗漏，不显示成“已是最新”。
3. 勾选目标，每批最多20项。更新器自身必须单独选择，不与普通批次混合。
4. 确认框默认等待当前任务自然结束。停止当前智能体活动必须额外同意：只针对确认时的活动，排队输入会清除，已完成的工具副作用不能撤销，之后启动的活动不被旧确认取消。外部终端和独立 Worker 不会被杀掉。
5. 先核验包和状态，再处理任务并执行更新。逐项结果区分目标更新与旧版恢复；失败或需重启时停止／跳过后续项。**恢复成功不等于升级成功**。
6. 只有**结果已知、当前安装身份与记录匹配、原包可核验、恢复路径获准**的目标，才能单独确认恢复。未知结果和未获准路径的Union Search不因此获得恢复资格，不接受任意旧版本或路径。

DSH 不自动退出或重启。普通批次替换期间暂缓新步骤；自身升级的旧门禁在卸载时释放，不能保证宿主替换全程冻结新任务。开始替换前可取消等待；离开面板不取消已确认的宿主管理操作。未知结果不要连续重试。

## 支持范围

| 能力 | 限定条件 |
|---|---|
| 版本检查 | 区分发现新版与更新资格；展示查询源，不凭缺失结果宣称最新 |
| 普通 npm 更新 | 可移除的 profile 安装、兼容正式版、来源和归档预检通过；官方精确版本更新，保留 npm 来源并核验文件与 Host |
| 旧普通归档迁回 npm | 只对已识别、已核验的旧 Doctor 归档，同版本、独立确认；不适用于任意本地包、自身或 WSL |
| JS 依赖 | 标准通道允许依赖声明与 peer 变化：公开源＋目标归档字节核验后交给官方更新，装后按新清单核验实际解析树（拒绝原生字节、非法来源与安装脚本范围），不通过自动回滚 |
| Better Sidebar | 常规标准通道；`!!js` 停用声明作为惰性 YAML 数据解析、不执行，不再保存版本对 |
| WSL | 公开原包、代际打包契约、实际安装身份与全部保留原包证明；行集合和 `!!js` 表达式不再逐版本审查 |
| 更新器自身 | npm、固定公共镜像／备用源或固定 GitHub 完整提交；独立确认与官方 Host 交接，不静默迁移来源 |
| Union Search 等纯 JS 依赖插件 | 按安装结构与原包证据准入的完整依赖隔离路线；不保存版本白名单，宿主声明变化按新版本自身声明重新打包并在装后核验；新声明缺少的依赖从公开 npm 下载并嵌入代际 |

### npm 自身更新与公共备用源

支持官方 npm、固定 `registry.npmmirror.com`，以及两者构成的已核验公共备用源计划。不写入用户 registry／fallback 配置。

- 默认源 `registry:null` 通过官方 API 的前后稳定快照解释，不直接视为未知来源。
- 镜像／备用源风险需要额外确认；可能使用的镜像旧、新更新器原包必须与官方同版本归档一致。私有、未知、带凭据的来源或不可核验的原包仍拒绝。
- npmmirror 归档仅允许精确同包同版本路径单跳到固定 `cdn.npmmirror.com`，禁止任意地址、凭据、query/hash、路径变体和第二跳；最终仍核验完整性与官方摘要。
- 确认绑定完整宿主源计划；预检前后、停止任务前、等待后和实际交接前重验。确认之后新增备用源也不能当作已同意。
- Host 仍会重新下载并使用其原有计划。预检包是证据，**不是原子替换或精确字节安装保证**。

### 普通镜像下载与依赖变化

0.5.5将精确 npmmirror CDN 单跳支持扩展到普通插件预检，并继续校验 SRI、运行声明和官方同版本摘要；不允许任意跳转或第二跳。失败提示区分包详情、归档下载、跳转拒绝和内容不一致。

0.6.0 起普通插件不再因依赖或 peer 声明变化被预拒绝。`dsh-better-sidebar` 的 `!!js` 停用声明作为惰性数据解析（只校验 YAML 形状，不执行表达式），`0.32.1 → 0.33.0` 的依赖收缩与其他依赖变化走同一路径：官方 registry 更新后按新清单核验实际解析树与 Host 行，失败自动回滚原归档。0.5.5 的固定版本对与摘要登记已删除。

### 纯 JS 依赖隔离路线

有的插件在新进程里能正常加载，但在当前进程卸载再安装后，会复用旧依赖的加载状态而失败；Union Search 的官方常规热更新和自动恢复在 0.2.2-rc.5 上已复现这一类失败。0.5.6 起改为**按结构准入**，不再按版本号逐对放行：

- 依据**已安装包的真实依赖声明**选择路线，而不是保存的版本名单。同一结构下的后续正式版沿用同一路线，不需要再次改代码。
- 旧、新公开原包的宿主声明不再要求逐字节一致：代际从新版本自身声明生成，装后核验行、导出与运行命名空间。依赖声明按范围比较：已核验闭包满足的部分直接复用，满足不了的范围从公开 npm 下载并按 npm 语义放置（不同大版本可并列），构建自包含代际后再核验。单一静态行之外的动态或嵌套声明仍拒绝。
- 运行依赖必须是可核验的纯 JS 闭包：拒绝原生模块、生命周期脚本、workspace／Git／文件依赖和可选依赖；每个物理副本都与公开 npm 原包逐字节比对。
- 更新前同时生成**目标**和**不同 token 的旧版恢复**代际归档；原始 JS 与资源字节不改，只把入口路由到全新路径。
- 完成条件不是“安装命令退出 0”：必须官方管理器 applied、当前安装字节一致、Host 行激活，且 Loader 实际运行的是那个新路径的模块。
- 未知结果不重发；恢复失败如实标为失败。安装来源会变为更新器管理的本地归档，需要单独确认，不伪装成 npm 安装。

详见[依赖隔离说明](<docs/ISOLATED_DEPENDENCIES_0_5_6.md>)。

### GitHub 自身更新

只查询固定公开仓库 main HEAD 上更高的正式包版本，并在确认时绑定完整提交；不是签名 Release，也不提供同版本提交替换、降级或预发布更新。原包、Git tree／blob摘要、打包控制、固定 YAML／助手与不变运行声明都要核验。Git交接的依赖沿用宿主现有源，不批准脚本或迁移来源。

GitHub 无凭据 API 受出口IP配额限制。遇到限流时应稍后检查，不自动切到 npm，也不会索取或保存令牌。详情见[自身升级规则](<docs/SELF_UPDATE.md>)。

### WSL 与 Union 的代际语义

WSL保留旧根资源、历史导出与全部原包证明，新 Host 条目和新会话使用新代际；已有会话可能继续使用旧预设。**Host 更新成功不等于所有 WSL 会话强制换代**，不调用只适用于空白会话的重绑入口绕过锁定。0.6.0 起未来正式版直接进入代际打包，行集合、`!!js` 表达式和导出键集合不再逐版本审查；核心供应者抑制与服务接管仍受保护。准入不等于未来执行已实测。见[WSL结构准入](<docs/WSL_STRUCTURAL_0_5_3.md>)。

Union常规 npm/HMR目标及旧版恢复在原版DSH rc.5实测加载失败。旧0.5.1的**风险拦截不算修复**。自0.5.2起使用完整依赖本地代际：不修改原始JS或宿主，用全新路径保留旧资源和共享框架实例，提前准备fresh恢复。0.5.6把准入从固定版本对改为依据安装结构与原包证据，同一结构的后续正式版沿用同一路线。安装来源变为本地归档，内置Versions资格不保留，需额外确认。未知结果、不可核验代际或保留上限耗尽时拒绝，不静默删除旧代。见[Union代际说明](<docs/UNION_GENERATION_0_5_2.md>)与[依赖隔离说明](<docs/ISOLATED_DEPENDENCIES_0_5_6.md>)。

## 运行要求与验证范围

- **Windows x64**，DSH声明范围 `>=0.2.2-rc.3 <0.3.0`，实际插件运行Node **≥24**。最近完整隔离验证使用原版Desktop rc.5；兼容声明不是所有组合实测。
- YAML固定2.9.1由官方管理器安装。用户不需要开发源码、测试缓存或另装C#编译器。
- 只读文件使用助手需要 **.NET Framework 4.x** 与执行许可，不是自包含程序。诊断未知不表示没有占用，也不是所有更新路线的统一硬阻断。
- 网络、文件权限、杀毒软件、企业策略、重解析路径和外部占用仍可使检查／安装失败。每台设备重新核验当地状态，不复用本机测试结论。
- 0.6.15 去掉「一键更新」时的重复检查：直接复用你刚点过的检查结果（2 分钟内且覆盖所有已选项），不再把同一批包重新下载预检一遍；准备阶段 4 路并发，提交阶段去掉重复的依赖图遍历和提前的锁探针。每项记录实际用时，面板状态列显示时长。
- 0.6.14 删除「镜像一致性预比对」：预检查归档本就来自官方 npm，镜像一致性由装后逐字节核验覆盖；镜像来源少一次整包下载，也不再出现 `./bin` 一类误判。
- 0.6.13 修镜像来源误判：npm 元数据会把 `bin` 里的 `./` 去掉，与 tarball 字面不一致，之前被判「镜像声明不一致」；现在按路径规范化后比较。
- 0.6.12 面板行上直接标出「宿主包依赖」（`⚠ 宿主包依赖` + 详情列出具体包），文案明确不拦截；没有这种依赖的插件不显示。
- 0.6.11 又测 20 款（17 成功），新增 `hostDependencies` 记录：目标把 `@deepseek-ai/*` 写成普通依赖时会在计划里标出（pnpm 会把它提到 profile 根部，DSH 可能停用对应核心行），但仍不拦。
- 0.6.9 只留「能回滚」的前提：安装脚本、`git:`/`http:` 依赖、宿主运行时依赖、新增核心接线、原生依赖都不再预拒，只在结果里记录；面板几乎不再出现「不支持在线更新」。唯一代价：新 patch 若让宿主起不来，回滚跑不到，需要手动处理。
- 0.6.8 按「少拦、装完看事实、坏了回滚」砍掉静态形状门槛：patch 行名/group 行/相对模块路径/打包依赖/归档里的原生文件都不再预拒，只记录；装后依赖范围不符改为**警告并继续**。仍拒的只剩回滚救不回来的六类（安装脚本、`git:`/`http:` 依赖、宿主运行时依赖、新增核心行接线、非公开源、自身/宿主管理包）。
- 0.6.7 第二轮实测 10 款真实插件（先装旧版再升级），修掉四处误伤：`agent-compare` 这类命名行被当成核心行接管；`prepare` 构建脚本被当成安装脚本；依赖树不可用时恢复记录校验崩溃；`^0.12` 这类两段式版本范围被误判为「依赖版本不符」。装后核验失败现在会带上具体原因。
- 0.6.6 拿 5 款真实社区插件做端到端实测：4 款直接升级成功（含一次把损坏的旧版升成可用新版），1 款在官方 pnpm 抓取时断网、旧版保留且未误报。同轮修掉两类问题：patch 里带 override 的插件不再被永久挡住（只在**新增/改动**核心服务接线时才判 `core-service-takeover`），网络抖动不再被说成「选择已变化」（`version-query-failed` / `preflight-network-failed`，可重试）。同一轮还实测了「先安装再立即更新」与「一次确认批量三件」。
- 0.6.5 确认弹窗去掉两个来源勾选框（说明文字保留，服务端显式确认不变），「检查全部更新」加真实进度条（阶段、当前插件、完成数/总数、百分比）。
- 0.6.4 提速检查：只读预检查复用已验证的公开归档（不再每次全量下载旧包），网络失败如实标为可重试，不再伪装成策略拒绝。
- 0.6.3 补齐错误反馈：最近 10 次失败详情单独保留（不占历史预算），复制诊断失败时直接显示可选中 JSON，并把当前面板错误一并写进报告。
- 0.6.2 增加**复制诊断报告**：工具栏、失败结果行和详情页都能复制一段脱敏 JSON（版本、错误码、步骤、恢复记录与安装器日志），反馈时直接附上，不再需要用户自己翻缓存目录。
- 0.6.1 接入**依赖闭包下载**：隔离代际只下载已核验闭包满足不了的部分，按 npm 的 owner/嵌套语义放置，不同大版本不再判冲突；下载前给出包数与体积，归档按发布 SRI 逐个校验，篡改在准备阶段即被拒。自有 Host 证明覆盖真实 0.11.0 → 合成 0.11.1（新增真实依赖）的下载、目标失败恢复与再次成功，运行命名空间与 `advance_fetch` 均验证。
- 0.6.0 改**标准通道**：只要求公开源、目标归档字节核验和旧版本回滚归档；不再因 peer 图、依赖声明、WSL 结构／`!!js` 表达式或 Better Sidebar 版本对而预拒绝。装后按新清单核验实际依赖树与 Host 行，不通过自动回滚。隔离路线的依赖范围变化在 0.6.0 仍要求已核验闭包满足，0.6.1 起可下载补齐。
- 0.5.11 放宽隔离路线的依赖变化：新版本调整依赖**范围**时，只要已核验闭包已满足新范围就继续用现有副本；闭包满足不了才拒绝（`dependency-closure-requires-download`）。
- 0.5.10 去掉停止任务前的第二个勾选框：选择「停止当前智能体任务后更新」本身就是同意，确认按钮写明停止语义；宿主仍要求显式 `confirmCancel`。
- 0.5.9 收窄 WSL 声明审查：结构（行集合与核心覆盖）继续钉死；配置数据变化直接放行并在面板显示差异；`!!js` 表达式改为**按表达式摘要审查**，已审查的可复用，只有新表达式才要求审查。0.29.1 因此可以走更新，不再按版本逐一修。
- 0.5.8 增加**重启式更新**：宿主拒绝就地卸载时，把已核验的目标写盘并记录待核验项，下次启动由更新器核验字节、宿主条目与运行命名空间；不通过则自动回滚原版本并再次要求重启。
- 0.5.7 修掉一种半完成状态：官方删除返回 `restart-required` 且磁盘已变时，立即用暂存原版本回滚并核对字节，绝不把插件留在“已删除、未安装”。面板按 `docs/UI_SIMPLIFICATION_NOTES.md` 简化，技术证据收进一个折叠区块。

## 安全与隐私

官方 `pluginManager` 处理安装和配置，不手改 profile、不改DSH／Node／Electron、不强清缓存、不提权、不批准脚本或版本豁免。文件使用助手只查询元数据与Restart Manager列表，不关闭用户进程或强制解锁。

历史结果、实际文件、Host加载与页面同步分别观察。未知、持久化失败或外部状态变化时不标成功、不重发或覆盖外部安装。本机有界诊断不上传；分享前仍须人工删除凭据、完整目录、用户名和会话内容。
