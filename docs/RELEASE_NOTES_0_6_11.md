# v0.6.11：20 款插件实测，宿主包依赖改为可见警告

这版只加了一处**记录**，没有新增任何拒绝；同时补记这一轮 20 款插件的实测结果。

## 这一轮 20 款的结果

| 结果 | 数量 | 说明 |
| --- | --- | --- |
| 更新成功 | **17** | 版本替换、来源、字节、Host 行全部核验通过 |
| 装不上旧版 | 3 | 都在「官方安装」阶段失败，没有进入我们的流程 |

失败的 3 款与原因：

| 插件 | 原因 |
| --- | --- |
| `dsh-paste-path` 0.1.2 | `incompatible-version`：声明的依赖范围只覆盖 DSH 0.0.x–0.1.x |
| `dsh-session-fork` 0.3.0 | `incompatible-version`：peer 仍指向 DSH `0.1.0-rc.7` 那一代包 |
| `dsh-file-bookmark` 0.1.6 | 把 `@deepseek-ai/dsh-tools@0.1.7-rc.2` 写成**普通依赖**，pnpm 把它提到 profile 根部，DSH 检测到与 0.2.2 不兼容后**停用了核心 `tools` 行**，于是它自己和其他依赖 `tools` 的插件都停在 `pending (waiting for service: tools)` |

## 本版改动：把「宿主包依赖」记为警告

`dsh-file-bookmark` 这种写法会让包管理器把旧版宿主包放到 profile 根部，进而让 DSH 停用核心行。我们不再拦它（按你的方向），但会把它**记录下来**：

- 检查结果里多一个 `hostDependencies` 字段，列出目标包声明的 `@deepseek-ai/*` 依赖；
- 计划里同样带上该字段，失败时一眼能看出是「它把宿主包塞进了 profile」，而不是我们的判断；
- 不改变是否允许更新。

## 验证

- 回归 **447 项通过**（Node 24 串行），新增 1 项：声明宿主包依赖时会被记录且仍然放行。
- 打包与冒烟见 `artifacts/release-0.6.11/`。

## 限制

- 20 款仍是样本；每个只测一对版本。
- `incompatible-version` 与「宿主行被停用」属于 DSH/包管理器自身判定，我们只记录与回滚。
- 浏览器渲染/点击未验收。
